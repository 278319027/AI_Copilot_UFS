## 阶段 1：Open（开启）

### 流程
```
/comet-open → 加载 openspec-explore → 探索需求 → 澄清 → 创建 change → 用户确认
```

### 需求交互

| 轮次 | 系统提问 | 用户回答 | 决策点 |
|------|---------|---------|--------|
| 1 | 哪种平衡树？AVL/红黑树/其他？ | `AVL，算法学习` | — |
| 2 | 操作集、键类型、位置、注释风格？ | `C语言开发，其余默认是` | 纠正：项目是 TS，C 放哪？ |
| 3 | C 文件放哪？`examples/` / 独立 / 单独项目？ | `A (examples/avl-tree/)` | — |

### 澄清确认（阻塞点 1b）

```
目标:    examples/avl-tree/ 下实现 C 语言 AVL 树，学习用途
非目标: 不集成 TypeScript 构建，不做可视化/性能测试
范围:   insert / delete / search / 中序 / 四种旋转
键类型: int，不允许重复
命名:   待确认
```

→ 用户确认：`正确`

### Change 命名（阻塞点 1c）

| 推荐名称 | 范围 |
|---------|------|
| `avl-tree-example` | 示例/学习代码 |
| `c-avl-tree` | C 语言实现 |
| `avl-tree-algorithm` | 算法本身 |

→ 用户选择：`2 (c-avl-tree)`

### 产物创建

```
openspec new change "c-avl-tree"
  → openspec/changes/c-avl-tree/

标准产物循环:
  openspec instructions proposal → proposal.md
  openspec instructions design   → design.md  
  openspec instructions specs    → specs/avl-tree/spec.md
  openspec instructions tasks    → tasks.md (7组 / 11个任务)
```

### 状态初始化
```bash
comet-state init c-avl-tree full
  → .comet.yaml: {workflow: full, phase: open}
```

### 用户审视（阻塞点 5）

展示 proposal / design / tasks 摘要 → 用户要求调整：
- 函数名改 camelCase
- if/for/while 强制花括号

修改后再次确认 → `确认，继续下一阶段`

### 退出
```bash
comet-guard c-avl-tree open --apply
  [PASS] proposal.md ✓
  [PASS] design.md ✓
  [PASS] tasks.md ✓
  → phase = design
```

## 阶段 2：Design（深度设计）

### 流程
```
/comet-design → 生成交接包 → 加载 brainstorming → 逐个澄清 → 确认方案 → 写入 Design Doc
```

### 工具链

```bash
comet-state check c-avl-tree design          # 入口验证
comet-handoff c-avl-tree design --write      # 生成交接包
  → design-context.json + design-context.md
```

### Brainstorming 交互

| 轮次 | 问题 | 回答 | 决策 |
|------|------|------|------|
| 1 | 返回值约定：输出参数 / 错误码 / 包装结构体？ | `A（输出参数 int *ok）` | insert/deleteNode 返回新根，*ok 指示成败 |
| 2 | 需要 freeTree 吗？ | `B（需要）` | 后序遍历释放，配合 valgrind |
| 3 | main.c 交互程度：纯脚本式 / REPL？ | `A（纯脚本式）` | `./avl-test insert 10 20 30` |

### 设计方案确认（逐段）

| 段落 | 内容 | 确认 |
|------|------|------|
| API 与错误处理 | avl.h 函数签名 + 返回值约定 | ✅ |
| 核心算法流程 | insert 流程图 + 旋转分派逻辑 | ✅ |
| 文件组织与构建 | 文件清单 + Makefile + main.c 用法 | ✅ |

### 产物

```
brainstorm-summary.md          # 增量落盘（压缩恢复用）
docs/superpowers/specs/
  2026-07-02-c-avl-tree-design.md   # 正式 Design Doc（含 API/算法/测试策略）
```

### 退出
```bash
comet-state set c-avl-tree design_doc docs/superpowers/specs/2026-07-02-c-avl-tree-design.md
comet-guard c-avl-tree design --apply
  [PASS] ×12
  → phase = build
```

## 阶段 3：Build（计划与构建）

### 流程
```
/comet-build → 制定计划 → plan-ready 暂停点 → 选择工作方式 → 创建分支 → 加载 executing-plans → 逐任务执行
```

### 决策点

| 决策 | 选项 | 用户选择 |
|------|------|---------|
| plan-ready 暂停 | 继续 / 暂停 | `继续执行` |
| 工作区隔离 | branch / worktree | `branch` |
| 执行方式 | executing-plans / subagent-driven | `executing-plans` |
| TDD 模式 | direct / tdd | `direct` |
| 代码审查 | off / standard / thorough | `standard` |
| 分支名 | feature/20260703/c-avl-tree / 自定义 | `确认推荐名称` |

### 状态写入
```bash
comet-state set c-avl-tree plan docs/superpowers/plans/2026-07-02-c-avl-tree.md
comet-state set c-avl-tree isolation branch
comet-state set c-avl-tree build_mode executing-plans
comet-state set c-avl-tree tdd_mode direct
comet-state set c-avl-tree review_mode standard
```

### 实施计划（6 Tasks）

```
Task 1: 项目骨架     → Makefile + utils.h         → ✅ commit
Task 2: 基础数据结构  → avl.h + newNode + search   → ✅ commit
Task 3: 旋转 + 插入   → rotate* + insert           → ✅ commit
Task 4: 删除 + 遍历   → deleteNode + inorder + freeTree → ✅ commit
Task 5: 测试入口      → main.c (多子命令链)        → ✅ commit
Task 6: 全场景验证    → 10 个 spec 场景            → ✅ commit
```
