# 行为上下文报告

可合并到现有阶段产物，不要求每函数一个文件。报告较大时用索引链接行为切片，交接摘要只保留结论、来源位置和待决责任。

## 最小内容

1. **范围**：待支持的工程决定、现有 Story/AC/约束或候选目标引用、问题与入口、代码/工作树版本、目标构建配置、资料状态、Owner、实际已读及相关未审范围。
2. **行为**：参与者、关键状态、成功/失败时序、完成与观察边界，绑定源码位置。
3. **前提链**：前提、使用者、代码或外部保证机制、精确依据、目标配置下是否满足、使用前可能破坏它的路径及剩余验证责任。
4. **跨函数不变量**：应保持的关系及来源；哪些路径建立/维护/消费它；哪些仍无法判断。实现推导与批准要求分开。
5. **交接**：受影响 AC/决定 → 行为解释 → 来源依据 → 可推翻解释的场景 → 所需观察/证据 → 下一责任人。保留关键未证实假设与冲突；共享结论注明各 Story 适用差异，不自动扩大范围。

对每个缺口区分“尚未调查”“已查范围未找到”“来源不可访问”“工具无法解析”。预算耗尽时标记部分完成并列出剩余工作，不把它们合并成不存在。

## 自检案例（假设，不是产品需求）

- 当前函数没有检查，但所有已确认入口都先检查：记录调用者保证及覆盖边界，不误称缺陷。
- 有效性检查与发布之间存在可变状态：定位可能的写入路径与同步条件，证据不足保持开放，不凭图推断竞态已发生。
- 回调实现不可读：写明依赖的回调保证未知，不仅根据接口名赋予成功语义。
- 只读了成功分支：报告不能宣称已理解失败后的资源生命周期。
- 保证来自调度合同：核对合同版本、目标配置和调度实现证据；只有合同声明时保留实现符合性待验，不能当作已保证或局部代码缺陷。
- 工程问题已得到解释：停止无关辅助函数展开；将未证明的高风险前提及后续责任明确交接。
