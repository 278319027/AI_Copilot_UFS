# Concurrency Rules

SSD 固件并发安全规则。AI 生成代码时必须遵守以下规则，Review 时必须检查以下规则。

## 1. volatile 规则

- 所有硬件寄存器访问必须使用 volatile 限定符。
- ISR 与主循环共享的变量必须使用 volatile。
- ISR 与任务共享的变量必须使用 volatile。
- volatile 变量不得被编译器优化掉（禁止寄存器缓存优化）。
- 多核共享变量必须使用 volatile + 内存屏障。

## 2. 中断安全规则

- ISR 中禁止调用可能阻塞的函数。
  - 禁止：malloc、free、printf、semaphore_take、mutex_lock、sleep、delay。
  - 允许：信号量 give、事件 set、队列 send（非阻塞版本）。
- ISR 中禁止调用非可重入函数。
- ISR 与主循环共享的标志变量必须使用 volatile + 适当屏障。
- ISR 必须尽可能短，数据处理交给主循环或任务。
- ISR 中只做：清除中断标志、读取数据、设置标志、触发任务通知。

## 3. 锁规则

- 锁的获取顺序必须全局一致（定义锁层级）。
  - 示例：锁层级定义 → NVMe 锁 > FTL 锁 > Buffer 锁 > NAND 锁。
  - 禁止反向获取：持有 NAND 锁时不得尝试获取 FTL 锁。
- 禁止在持有锁时调用可能阻塞的函数。
- 禁止在 ISR 中获取互斥锁（可用自旋锁）。
- 自旋锁用于中断上下文，互斥锁用于任务上下文。
- 锁必须成对获取和释放，每个 return 路径都必须释放。
- 锁持有时间必须最短化，禁止在锁内调用外部模块函数。

## 4. DMA 规则

- DMA 缓冲区必须对齐（cache line 对齐，通常 32 或 64 字节）。
- DMA 传输前必须刷新 cache（源地址：cache flush）。
- DMA 传输后必须无效 cache（目标地址：cache invalidate）。
- DMA 缓冲区在传输期间不可被 CPU 修改。
- DMA 完成标志必须使用 volatile + 适当屏障。
- DMA 传输描述符必须与非 DMA 数据分开存放。
- 禁止在 DMA 传输进行中释放对应缓冲区。

## 5. 原子操作规则

- 映射表更新必须原子（或使用 Copy-on-Write）。
- 命令状态机转换必须原子。
- 引用计数必须使用原子操作（__atomic_fetch_add / __atomic_sub_fetch）。
- 断电路径中的全局状态更新必须原子。
- 原子操作不得被拆分为读-改-写三步（必须使用 LDREX/STREX 或 __atomic 内建函数）。

## 6. 多核安全规则

- 多核共享变量必须使用 volatile + 内存屏障。
- 自旋锁必须使用 DMB/DSB 指令保护。
- 多核间通知必须使用硬件事件（SEV/WFE）或邮箱中断，不得使用忙等轮询。
- 每核私有数据必须使用 CPU ID 索引，避免 false sharing（每项对齐到 cache line）。
- 多核共享队列必须使用无锁队列或带锁队列，禁止无保护的双端操作。

## 7. 常见并发陷阱

以下模式在 Review 中必须重点检查：

- 双重检查锁定（Double-Checked Locking）：在无内存屏障的平台上不安全，禁止使用。
- 忙等循环（Busy Wait Loop）：ISR 或高优先级任务中禁止使用 while 等待标志。
- 优先级反转：高优先级任务等待低优先级任务持有的锁时，必须使用优先级继承协议。
- 死锁检测：如果锁层级定义正确，理论上不会死锁。但代码中必须包含死锁超时机制。
- 异步回调重入：同一回调函数可能被不同上下文调用时，必须保证重入安全。
