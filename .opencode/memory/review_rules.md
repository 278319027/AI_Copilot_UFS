# Review Rules

SSD 固件代码 Review 规则。AI Review 代码时必须遵守，人工 Review 时必须检查。

## 1. 重点检查项

### 1.1 内存安全

| 检查项 | P0/P1/P2 | 典型问题 |
|--------|-----------|----------|
| 空指针解引用 | P0 | 未检查 `malloc` 返回值（虽然固件禁用 malloc，但 buffer 池分配也可能返回 NULL） |
| 数组越界 | P0 | LBA 未校验范围、Page index 未校验上限 |
| 未初始化变量 | P0 | 结构体未完整初始化、局部变量使用前未赋值 |
| DMA 缓冲区对齐 | P0 | 未按 cache line 对齐、未做 cache 操作 |
| 栈溢出 | P0 | 局部数组过大、递归调用（固件中禁止递归） |
| Use-after-free | P0 | Buffer 释放后仍被引用 |

### 1.2 并发安全

| 检查项 | P0/P1/P2 | 典型问题 |
|--------|-----------|----------|
| 竞态条件 | P0 | 多核/多任务对同一数据无保护访问 |
| 死锁风险 | P0 | 锁获取顺序不一致 |
| ISR 安全 | P0 | ISR 中调用阻塞函数 |
| volatile 缺失 | P1 | ISR 共享变量未加 volatile |
| 锁持有时间 | P1 | 锁内调用外部模块或做 I/O |

### 1.3 逻辑错误

| 检查项 | P0/P1/P2 | 典型问题 |
|--------|-----------|----------|
| 死循环 | P0 | while 条件永不假、中断未触发导致无限等待 |
| 逻辑分支缺失 | P0 | switch 缺少 default、if-else 未覆盖所有情况 |
| 错误路径静默 | P0 | 错误返回值未检查、失败路径无日志 |
| 资源泄漏 | P0 | Buffer/锁/中断未释放 |
| 状态机不完整 | P1 | 缺少状态转换、缺少超时处理 |

### 1.4 接口兼容性

| 检查项 | P0/P1/P2 | 典型问题 |
|--------|-----------|----------|
| 函数签名变更 | P1 | 参数类型/数量/顺序变化，调用方未更新 |
| 结构体布局变化 | P0 | 字段顺序、对齐、大小变化，导致二进制不兼容 |
| 宏定义变化 | P1 | 宏值变化，影响编译行为 |
| 头文件变更 | P1 | 新增/删除接口，影响依赖方 |

### 1.5 NAND 特有问题

| 检查项 | P0/P1/P2 | 典型问题 |
|--------|-----------|----------|
| 同一 Page 重复写 | P0 | NAND 不允许同一 Page 写两次（部分程序例外） |
| 擦除前写 | P0 | NAND Block 必须先擦除再写 |
| 坏块未跳过 | P0 | 写入前未检查 Block 坏块标记 |
| ECC 能力不足 | P1 | 校验位不够纠正当前位错误数 |
| Write Disturb | P1 | 频繁写入相邻 Page 导致数据翻转 |

## 2. 风险等级定义

### P0：数据安全或功能正确性风险

- 可能导致数据丢失
- 可能导致系统死机/挂起
- 可能导致量产失败
- 可能导致 NAND 数据不可恢复

**P0 问题必须修复后才能合入。**

### P1：功能异常或严重性能问题

- 可能导致功能异常（但不会丢数据）
- 可能导致性能显著下降
- 可能导致兼容性问题

**P1 问题必须在当前版本修复。**

### P2：可维护性或低风险缺陷

- 代码风格不一致
- 注释缺失或过时
- 性能微优化空间
- 非关键路径的防御性编程缺失

**P2 问题建议修复，但不阻塞合入。**

## 3. Review 输出要求

### 3.1 格式

```markdown
## Review 结果摘要

- 总问题数：X（P0: Y, P1: Z, P2: W）
- 影响范围：模块A、模块B
- CodeGraph 影响分析：[结果]

---

### P0 问题

| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|
| 1 | nand.c:256 | 空指针未检查 | 数据丢失风险 | 增加 NULL 检查 |

### P1 问题

| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|
| 2 | ftl.c:102 | 锁顺序不一致 | 死锁风险 | 统一按层级获取 |

### P2 问题

| # | 文件:行号 | 问题描述 | 影响 | 修复建议 |
|---|-----------|----------|------|----------|
| 3 | nvme.c:45 | 注释过时 | 可维护性 | 更新注释 |
```

### 3.2 规则

- 先列高风险问题（P0 > P1 > P2）。
- 每个问题必须给出文件位置、原因、影响和建议。
- 不允许只给结论不解释。
- 特别关注 NAND 和并发相关 P0 问题。

## 4. CodeGraph 辅助 Review

### 4.1 变更前必须查询

1. 用 `impact` 查询变更文件的影响范围
2. 用 `codegraph_callers` 验证修改函数的所有调用方
3. 用 `find_by_imports` 验证修改头文件的所有包含方
4. 用 `get_dependency_graph` 验证模块边界是否被破坏

### 4.2 特别关注

- 函数指针调用：CodeGraph 可能遗漏，用 `symbol_search` 查函数指针表注册点 + 手工读 dispatch 函数
- 宏使用：`find_by_pattern` 确认
- 中断上下文：标注哪些函数在 ISR 路径上，中断安全必须额外检查

### 4.3 Review 声明

每条 Review 输出必须注明 CodeGraph 验证结果：
- "CodeGraph 确认影响范围：3 个文件、5 个调用方"
- "CodeGraph 未覆盖：函数指针调用 2 处（已用 symbol_search + 手工确认）"
