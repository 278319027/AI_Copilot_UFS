# 硬件知识库说明

## 目录结构

```text
.opencode/knowledge/
├── nand_controller/
│   ├── registers.md     # NAND 控制器寄存器定义和配置顺序
│   ├── operations.md     # NAND 操作序列和命令码
│   └── constraints.md    # 时序约束、并发约束、错误恢复
├── nvme_spec/
│   ├── admin_commands.md # NVMe Admin 命令集和数据结构
│   └── io_commands.md   # NVMe I/O 命令集（待补充）
└── platform/
    ├── memory_map.md     # 系统内存映射、中断分配、时钟树
    └── power_states.md  # 电源状态转换（待补充）
```

## 使用原则

1. **只包含 AI 无法从代码推断的隐性知识**：
   - 寄存器地址、配置顺序、时序参数 ✅
   - 命令码、操作序列约束 ✅
   - 中断优先级、时钟配置顺序 ✅
   - 函数签名、数据结构定义 ❌（代码可推断）

2. **每个文件不超过 2000 行**（控制 token 开销）。

3. **按 Skill 粒度拆分，按需注入而非全量注入**：
   - 处理 NAND 驱动代码时，注入 `nand_controller/` 目录的知识。
   - 处理 NVMe 命令处理代码时，注入 `nvme_spec/` 目录的知识。
   - 处理平台相关代码时，注入 `platform/` 目录的知识。

4. **每个文件模板化**，包含填写说明：
   - 模板中标注了需要替换为实际芯片值的占位符。
   - 不同芯片型号有不同的填写文件。

5. **版本绑定**：
   - 每个知识文件必须标注适用的芯片型号和固件版本。
   - 修改知识文件时，必须同步更新版本号。

## 与可行性报告的对应

> 本知识库的设计来自《固件AI辅助编程探索.md》第 7.1.2 节的建议：
> "建立硬件知识库 — 将 NAND 控制器寄存器手册、NVMe 规约关键段落结构化注入"。

与 RespCode 的 MCU Knowledge Injection 方法论一致：
- 在模型写代码之前，先提供精确的硬件数据。
- 模型不需要猜测或回忆寄存器地址，而是直接获得。
- 通过对照 SVD 数据库交叉验证寄存器地址。
