## 1. ECC 纠错

### 1.1 ECC 能力配置

| 配置项 | 值（填写实际芯片值） | 说明 |
|--------|----------------------|------|
| ECC 纠错能力 | ___ bit / ___ Byte | 每多少字节可纠正多少位错误 |
| ECC 检测能力 | ___ bit / ___ Byte | 检测但不可纠正的位数 |
| ECC 码长 | ___ Byte | 每页/每 Chunk 的 ECC 校验字节长度 |
| 最小纠错单元 | ___ Byte | ECC 引擎的计算粒度（512B/1024B） |
| 原始误码率(RBER) | ___ | 新品状态下的原始位错误率 |
| 目标误码率(UBER) | ___ | 纠错后的不可纠正位错误率目标 |

### 1.2 ECC 引擎操作序列

```text
写入路径：
1. 填充数据到 DMA 缓冲区
2. 配置 ECC 引擎为 Encode 模式
3. 启动 DMA 传输（数据 → NAND）
4. ECC 引擎自动计算校验码并附加到页末尾
5. 等待传输完成

读取路径：
1. 配置 ECC 引擎为 Decode 模式
2. 启动 DMA 传输（NAND → 数据缓冲区）
3. ECC 引擎自动校验并纠错
4. 检查 ECC 状态：
   - 成功（无错误或已纠正） → 继续处理
   - 可纠正但超过阈值 → 标记弱块，继续处理
   - 不可纠正 → 进入错误处理流程
```

### 1.3 ECC 错误分类

| 错误类型 | 位错误数 | 处理策略 |
|----------|----------|----------|
| 无错误 | 0 | 正常通过 |
| 可纠正 | 1 ~ 阈值 | 纠正后通过，累计计数 |
| 可纠正但接近阈值 | 阈值附近 | 标记弱块，触发数据搬迁 |
| 不可纠正 | > 检测能力 | 标记坏块，尝试数据恢复 |

### 1.4 弱块标记与数据搬迁

- 弱块定义：ECC 纠错位数超过设定阈值（如 50% 纠错能力）。
- 弱块处理：
  1. 读取弱块中所有有效页数据。
  2. 将数据搬迁到新块。
  3. 更新映射表。
  4. 标记弱块为坏块（可选：先标记为弱块，超过上限后标记为坏块）。
- 弱块阈值必须可配置（不同 NAND 类型、不同生命周期阶段可能不同）。

## 2. 坏块管理

### 2.1 坏块类型

| 类型 | 来源 | 标记时机 |
|------|------|----------|
| 出厂坏块 | 厂商出厂标记 | 初始化时扫描 |
| 增长坏块 | 使用中产生 | ECC 不可纠正 / 编程失败 / 擦除失败 |
| 弱块 | ECC 纠错位数接近上限 | 读取时检测 |

### 2.2 出厂坏块扫描

```text
初始化流程：
1. 从最后一个 Block 开始向前扫描（出厂坏块标记通常在最后 1-2 页）
2. 读取每个 Block 的坏块标记页
3. 检查以下位置是否为非 0xFF：
   - SLC/MLC：第 1 页的第 ~__ 字节（填写实际芯片偏移）
   - TLC：第 __ 页的第 __ 字节
4. 非 0xFF 的 Block 标记为出厂坏块
5. 将出厂坏块表保存到 RAM 和 NAND 专用区域
```

> **注意**：出厂坏块的数据区可能已经包含厂商测试数据，但 spare 区有坏块标记。不要尝试擦除出厂坏块。

### 2.3 坏块表（BBT）数据结构

```c
typedef struct {
    uint32_t    total_blocks;         // 总 Block 数
    uint32_t    bad_block_count;      // 坏块总数
    uint8_t    *bad_block_map;         // 位图：0=好块，1=坏块
    uint32_t    bbt_block[MAX_BBT_COPIIES]; // BBT 存储位置（通常 2 份）
    uint32_t    bbt_version;          // BBT 版本号
    uint32_t    bbt_crc;              // BBT CRC 校验
} BadBlockTable_t;
```

### 2.4 坏块标记规则

- 出厂坏块：只读标记，不可清除。
- 运行时坏块：
  - 编程失败 → 立即标记为坏块。
  - 擦除失败 → 立即标记为坏块。
  - ECC 不可纠正 → 标记为坏块，尝试从冗余数据恢复。
- 坏块标记必须持久化到 NAND（更新 BBT）。
- 坏块标记更新必须原子化（双 BBT 交叉更新）。

## 3. 数据保护策略

### 3.1 数据搬迁流程

```text
数据搬迁（读-改-写）：
1. 读取源块所有有效页
2. 为有效数据分配新块
3. 将有效数据写入新块
4. 更新映射表（原子更新）
5. 擦除源块
6. 源块归还可用池

错误处理：
- 如果读取源块时 ECC 不可纠正 → 标记坏块，尝试其他恢复策略
- 如果写入新块失败 → 标记新块为坏块，重试分配其他块
- 如果擦除源块失败 → 标记源块为坏块
```

### 3.2 断电保护

- BBT 必须有双备份（两个不同 Block）。
- 更新 BBT 时：先写备份 1，再写备份 2，每次写入都带 CRC。
- 断电恢复时：比较两份 BBT 的版本号和 CRC，使用最新有效的那份。
- 如果两份都损坏（极低概率），从 NAND 重新扫描出厂坏块标记。
