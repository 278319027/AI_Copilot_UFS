# 判定与报告约定

以下是分析标签，不是运行时枚举。判定、检查完成度、独立复核状态和实际测试结果分别记录。

报告注明“基线差距分析”或“交付一致性审查”，逐项区分既有承诺、计划新增行为和本次声称交付行为。下列标签描述对照事实，不能脱离比较目的自动转成缺陷等级或 Gate 结论。

| 判定 | 含义 |
|---|---|
| 实现一致 | 在明确检查范围内找到满足来源要求的实现依据；不等于测试通过 |
| 部分实现 | 有实现依据，但部分要求/适用路径未满足；未调查路径应记录未检查而非直接判缺陷 |
| 实现矛盾 | 有具体实现行为与有效要求相冲突，附路径及成立前提 |
| 额外约束或行为 | 实现增加规范未描述的限制、依赖或行为；后果需单独判断 |
| 已查范围未找到实现 | 有搜索和阅读记录支持局部缺失判断，仍披露未覆盖范围 |
| 无法判断 | 规范模糊/冲突或关键代码、配置、环境证据不足，明确原因 |

## 最小报告

- 身份：当前阶段/Owner、比较目的、目标与现有实现边界、规范版本与批准状态、源码/工作树快照、构建配置。
- 覆盖：继承的 Story/AC/约束与来源 ID、已检查/未检查及原因、无法读取的资料；分支和子项保留父引用，原文核对发现的遗漏另交责任阶段，不建立平行产品清单。
- 对照表：Story/AC/约束 → 原文定位与行为解释 → 实现位置/路径或外部保证依据 → 判定与依据 → 测试/分析方式及限制。
- 差异记录：候选发现、触发条件、允许/实际行为、可复核证据、影响、反证尝试及结果、独立主体/状态、建议责任阶段。
- 反方向记录：规范未提及的实现行为及其实际影响。
- 交接：受影响 AC/决定 → 行为解释 → 来源依据 → 可推翻解释的场景 → 所需观察/证据 → 下一责任人；说明共享实现影响及未知边界，不自动将单项发现扩展到整个 Wave。

解释的复核状态可用“候选、独立支持、已撤回、存在分歧、未独立复核”表达；没有独立记录不得写独立支持。运行事实另记准确命令/环境/版本与原始结果，未运行即写未运行。撤回根因解释不删除失败事实，Reviewer 不可用不使失败变成通过。

## 自检案例（假设）

- 规范只规定结果，代码采用不同算法但满足结果：不能仅因机制不同判矛盾；若机制也是有效强制约束则另行核对。
- 单函数没有检查，但可达调用者统一建立前提：沿调用链核对后可撤回候选发现，记录覆盖限制。
- 故障分支绕过保证：说明分支可达条件、行为后果和证据，不能因正常路径成功判完整一致。
- 找不到关键词但没有检查宏/别名/间接调用：只能说明检索不足，不能宣布全局缺失。
- 独立 Reviewer 不可用：交付未复核解释与所需责任，保留已发生的失败及影响，不输出独立确认或 Accepted。
- Design 对照新 AC 发现尚无实现：记录计划实施差距及设计输入；同一缺口若发生在声称完成的交付范围，交 Build/Verify 处理。
- 保证位于有效调度合同但实现尚未核实：记录适用前提及待验责任，不能仅凭合同判实现一致。
- Build 已有失败日志但根因有争议：立即传递失败事实，独立反驳针对根因/规范解释，不等待复核才承认失败。
